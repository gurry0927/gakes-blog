## 1. 檔案系統（Filesystem）：硬碟「怎麼擺檔案」的規則

把硬碟想成一棟空大樓。**檔案系統**是這棟樓的「物業管理規則」——檔案放哪間房、怎麼編號、壞了怎麼救。

同樣一顆硬碟，用不同的檔案系統管理，能力就差很多。Linux 圈常見的有三個：

### ext4（你的 NAS 用的就是這個）
- Linux 預設，**穩定、簡單、夠用**
- 你的三顆盤（NVMe、紅標 HDD、備份盤）格式化時就是 ext4
- 缺點：它**不會自己驗證檔案有沒有腐爛**

> 「腐爛」是什麼？硬碟上的位元（0 和 1）會因為宇宙射線、磁力衰減、感應雜訊⋯⋯極小機率自己翻面。一張照片裡某個位元翻了，可能就變成一塊綠色色塊。這叫 **bit rot（位元腐敗）**。在大量長期儲存的場景（家庭照片庫）真的會發生。

### ZFS（TrueNAS 的招牌）
- 一個比 ext4 進階很多的檔案系統
- 招牌能力：**self-heal**——它會幫每個檔案算「指紋」（checksum），定期掃描，發現腐爛會自動從備援資料修復
- 還有：原生 snapshot（瞬間建立某個時間點的備份）、壓縮、加密、容錯陣列⋯⋯
- 缺點：吃 RAM、設計哲學跟一般 Linux 不太一樣、原本不是 Linux 親兒子（授權問題），所以 Ubuntu 雖然能用但不是 default

### Btrfs（ZFS 的 Linux 親兒子版）
- 概念跟 ZFS 像（self-heal、snapshot），整合在 Linux 核心裡
- Synology 新機種的 NAS 預設用這個
- 比 ZFS 年輕，少數複雜情境曾經傳出穩定性問題（已改善很多）

### 跟你有關的事
- 你的 NAS 三顆盤是 **ext4**（簡單可靠）
- 你**沒有 self-heal**——bit rot 真的發生時你不會知道
- 你的補救方式是 **rsync 7 天 hardlink snapshot**（→ 第一篇講過）：
  - rsync snapshot 抓的是「檔案層的副本」，不是「位元層的指紋」
  - 換句話說：如果某張照片的位元在你還沒發現前就腐爛了，**七天後你的快照也會跟著爛**（因為 rsync 會把腐爛的版本複製過去蓋掉舊的）
- 完整解法是 ZFS 或 Btrfs，但代價是換 OS 或重格盤
- **目前的判斷**：你一般使用＋7 天 snapshot 對「人為失誤」夠強；對 bit rot 是裸的。等你照片量真的大到（10TB+）、或開始有「20 年想保存」的需求時再升級

## 2. 其他 NAS / 伺服器 OS（你聽過 Ubuntu，但這圈子還有什麼？）

我在 #4 草稿裡提到 NixOS、Proxmox 你沒聽過——直接攤開：

### TrueNAS（你聽過的 NAS 專用 OS 之一）
- 內建 ZFS、有漂亮 Web GUI
- 點點點就能設共享、加備份、開服務
- 適合「想把 NAS 當家電用、不想學 Linux 的人」
- 缺點：要遷就它的設計哲學，加裝服務不像 Docker 那麼自由

### Unraid（半商用，要付錢）
- 招牌：**Parity 容錯**——你可以用一顆 4TB + 一顆 2TB + 一顆 1TB 組成一個容錯陣列，掛掉其中一顆能救回
- 這對「家裡剛好有幾顆不同大小舊硬碟」的人是神器
- 約 $59 USD 起跳的授權費（有試用）

### NixOS（小眾但很美的設計）
- 它把整台機器的設定變成**一份檔案**（declarative configuration）
- 你的 NAS 系統有什麼套件、什麼服務、什麼設定，全部寫在一個 `.nix` 檔
- 重灌的時候——你只要把這份檔案丟回去，**整台機器自動長回來**
- 概念上跟你的 INFRA.md 想做的事一樣（文件即基礎設施），但 NixOS 是「真的執行這份文件」而不是「給人讀的文件」
- 缺點：學習曲線非常陡，社群中文資料不多

### Proxmox（VM 王者）
- 它的核心定位是「跑虛擬機跟容器」
- 一台實體機可以裝 Proxmox，然後在裡面開 5 台 Ubuntu VM、3 台 Windows VM、10 個 LXC 容器
- 適合「我要把家裡實驗室搞得像迷你資料中心」的人
- 你目前是「Ubuntu 上跑一台 Windows VM」，量級夠小不需要 Proxmox

### 跟你有關的事
- 你**已經選了 Ubuntu Server**——這是合理的選擇，因為它跟你跟 AI 都熟（→ #4 整篇在講這件事）
- 如果未來你發現自己「想跑 10 台 VM」，可以考慮 Proxmox
- 如果你迷上「設定即程式碼」這個美學，可以玩玩 NixOS（但要花時間）
- 短期內不需要動現在這套

## 3. 「省壽命的四個小設計」：noatime / TRIM / hdparm / spindown

這四個東西彼此相關，一起講比較好懂。它們都是 Linux 對「磁碟壽命」的設計細節，你的 NAS 全部用上了。

### 先講「壽命」是什麼意思

- **HDD 的壽命**：機械結構（盤片在轉、磁頭在動）。**主要殺手是「總工作時間」**——轉得越久越接近壞掉。
- **SSD 的壽命**：沒有機械結構，但每個記憶體區塊有**寫入次數上限**（例如某些 SSD 是 600 TBW = 寫入 600 TB 後開始不保證）。**主要殺手是「總寫入量」**。

所以兩種盤要省壽命的方法不一樣：
- HDD → 想辦法**讓它盡量不轉**
- SSD → 想辦法**讓它盡量不寫**

下面四個設計就是為這兩件事服務的。

---

### noatime：每次讀檔，就少一次寫

預設情況下，Linux 每次「讀」一個檔案，會偷偷**寫**一筆紀錄上去：「這個檔案最後在 ⟨時間⟩ 被讀過」。叫 access time（atime）。

問題：你只是讀，卻發生了寫。一個正常使用的系統一天可能讀檔幾十萬次——換成幾十萬次「明明不用發生」的寫入。

**`noatime`** 就是告訴系統：「不要記這個了」。

→ **效果**：寫入量大概砍一半，對 SSD 是顯著延壽，對 HDD 是少很多次無謂喚醒。

→ **你的 NAS 設了沒？** 設了。看 `/etc/fstab`：
```
/  ... ext4 defaults,noatime 0 1
/data  ... ext4 defaults,noatime 0 2
/backup  ... ext4 defaults,noatime 0 2
```
三顆盤都掛了 `noatime`。這一行小設定就讓你的硬碟比預設配置長壽很多。

---

### TRIM：告訴 SSD「這些區塊我真的不要了」

SSD 跟 HDD 的物理特性差很多。其中一個重要差異：

- **HDD 刪檔**：硬碟物理上不需要做什麼，OS 標記「這塊空了」，下次寫東西直接覆蓋
- **SSD 刪檔**：SSD 內部得先「擦除」一個區塊才能重新寫入。如果它不知道哪些區塊已經被刪掉了，它會以為所有區塊都還在用，等到要寫的時候才現場擦——又慢、又增加磨損

**TRIM** 就是 OS 主動告訴 SSD：「這些區塊我真的不要了，你可以提前在背景擦掉它們。」

→ **效果**：寫入速度維持高、SSD 壽命延長

→ **你的 NAS 設了沒？** 設了。Ubuntu 預設啟用 `fstrim.timer`——每週日對所有 SSD 跑一次 TRIM。你完全不用管，自動跑。
```bash
systemctl status fstrim.timer    # 看狀態
systemctl list-timers fstrim.timer  # 看下一次什麼時候跑
```

→ **HDD 不需要 TRIM**——這個設計只對 SSD 有用。

---

### hdparm：HDD 的「設定遙控器」

`hdparm` 是一個指令工具，專門用來**對 HDD 下設定**。它本身不是常駐服務，比較像「一個遙控器」——開機時跑一次，把規則餵進 HDD 跟核心，之後就不管了。

它能做的事很多（讀寫快取、安全模式、NCQ⋯⋯），但你 NAS 上**只用它做一件事：spindown 設定**（下一段）。

→ **你的 NAS 設了沒？** 設了。`/etc/hdparm.conf` 裡：
```
/dev/sda { spindown_time = 240 }
/dev/sdb { spindown_time = 240 }
```
意思是「sda、sdb 兩顆 HDD 閒置就讓它們停轉」。

---

### spindown：HDD 閒置就停轉

HDD 的盤片預設會一直旋轉。它一旋轉就在磨損、就在耗電（約 8W）。

**spindown** = 「閒置一段時間就讓盤片停下來」。盤片停了：
- 機械磨損 → 0
- 耗電 → 從 8W 降到 < 1W
- 但要再讀檔時，要等 5–10 秒讓盤片轉回 7200rpm

**`spindown_time = 240`** 是什麼意思？這個值的單位很奇葩——**5 秒一格**。所以 240 = 240 × 5 秒 = **1200 秒 = 20 分鐘**。閒置 20 分鐘就停轉。

→ **效果**：你的 2TB 紅標 HDD 跟 500GB 備份盤，沒人用就在睡覺。第一篇講「一年大概省下 88 度電、壽命延長一倍」的根本原因就是這個。

→ **這也是為什麼 INFRA.md 第三條規則「不把 DB 放 HDD」**：DB 一直在讀寫，會把 HDD 永遠喚醒，spindown 完全失效。

---

### 四個設計如何一起運作

```
讀寫一個檔案
    │
    ├─ 在 SSD（如 PostgreSQL DB）
    │      └─ noatime 省掉 atime 寫入
    │      └─ 每週 TRIM 整理空閒區塊
    │
    └─ 在 HDD（如照片庫）
           └─ noatime 同樣省寫入＋少一次喚醒
           └─ 真的有人在讀寫 → HDD 醒著
           └─ 沒人讀寫 20 分鐘 → spindown 規則生效，盤片停轉
```

> 「為什麼 Linux 對 SSD 比 macOS 還溫柔」這個寫文章的角度其實很有東西——macOS 預設沒有 TRIM、要手動開、`noatime` 也不是預設。Linux 對儲存裝置的細節控制非常齊全。如果你想寫這篇，這份概念補課就是現成素材。

## 4. KVM：在 Linux 上跑 VM 的方法

你 NAS 上有一台 Windows 11 VM 跑在 KVM 上，但 KVM 到底是什麼？

### VM（Virtual Machine）= 一台「軟體模擬出來的電腦」

- 在你的 Ubuntu 之上，憑空生出**一整台電腦**：它有自己的 BIOS、自己的硬碟、自己的網卡、可以開機進入 Windows
- 對裡面的 Windows 來說，它根本不知道自己是被虛擬出來的
- 重點：這台「電腦」其實只是一個程式，磁碟是一個檔案（你的 `/opt/vm/windows11/` 裡那個 80GB 檔）

→ 跟 Docker 容器最大差別：容器**共用主機的 Linux 核心**（所以容器裡只能跑 Linux 程式）；VM **連核心都模擬出來**（所以可以跑 Windows、跑不同版本的 Linux、甚至跑 macOS）。代價：VM 比容器更吃資源。

### KVM = Linux 內建的「虛擬化引擎」

KVM 全名 Kernel-based Virtual Machine，從 2007 年就整合進 Linux 核心。它是**讓你 Linux 主機具備虛擬化能力的那一層底層引擎**。

但 KVM 自己沒有 UI、沒有指令工具，它只是核心裡的能力。你不會直接「用 KVM」，你會用上面包一層的工具來操控它：
- **`virsh`**（指令）：你看 VM 狀態用的 `virsh list --all` 就是這個
- **`virt-manager`**（圖形）：類似 VMware 的 GUI 視窗
- **`libvirt`**：底下的管理 daemon，virsh / virt-manager 都靠它跟 KVM 講話

### 跟你有關的事
- 你那台 Windows 11 VM，**底層引擎是 KVM**，**操控它用的指令是 virsh**
- 它**故意是關著的**（`shut off`），不是壞了——VM 一直開機太吃 RAM 跟 CPU
- 要用時：`virsh start windows11`，用完：`virsh shutdown windows11`
- 這也是 #3 段 4 的第二個 Docker 例外：你不可能把 Windows VM 包進 Docker，因為它需要的是「整台虛擬電腦」，不是 Docker 提供的「共用核心的隔離程序」

## 5. 備份空間怎麼算：你問的「大量搬東西要不要隔七天」

你的直覺是對的，但中間有幾個轉折值得釐清。

### 先講清楚 hardlink snapshot 的空間怎麼算

當你做 7 天 rolling snapshot：
- `/backup` 上實際佔用的空間 ≠ 7 份完整 `/data`
- `/backup` 上實際佔用的空間 = **「在這 7 天內出現過的不同檔案內容」總和**
- 同一份內容只佔 1 份空間，不管被幾個快照引用

### 舉例（用你 5/3、5/4 的真實事件）

5/3 那天 `/data` 多了 173GB 新內容（假設是新照片進 Immich）。在這之後：
- 5/3 的 snapshot 裡有那 173GB
- 5/4 的 snapshot 裡也指到同一份 173GB（hardlink，不重複佔）
- 5/5 ~ 5/9 的 snapshot 也都指到同一份
- **這 173GB 在 `/backup` 上待 7 天**——直到 5/10 凌晨清掉 5/3 的 snapshot 時，最後一個指過去的指標消失，那 173GB 才會釋放

### 所以「大量搬東西要隔 7 天」對嗎？

**部分對，但更精確的版本是這樣**：

✅ **真的對的部分**：
- 一次大量搬完 → 173GB 在 `/backup` 上佔 7 天就走
- 兩次大量搬隔太近（例如 5/3 173GB + 5/4 95GB）→ `/backup` 同時扛 173+95=268GB 的「7 天延後釋放」
- 隔 7 天再做下次大量搬，前一次那 173GB 已經完全清掉了，磁碟空間「歸位」再開始

❌ **沒那麼絕對的部分**：
- 如果是「搬資料夾 A 到資料夾 B」（內容沒變、只是換位置）——理論上 rsync 能識別，hardlink 不會增加佔用。**但實務上**很多搬移會觸發新 inode、metadata 變動，rsync 還是當新檔處理
- 如果是「刪舊增新」（例如清理一堆舊影片、加一堆新照片）—— `/data` 大小可能差不多，但 7 天內**舊的還在 snapshot、新的也在**，等於兩份都佔——這是最容易爆空間的場景

### 你應該怎麼判斷一次「大量搬東西」前要不要等？

實用的 checklist：

```bash
# 1. 看 /backup 現在多滿
df -h /backup

# 2. 估算這次要搬多少新內容（不是「移動」，是「會被 rsync 當新內容」的部分）
du -sh /要搬進去的目錄

# 3. 算一下：（目前 /backup 已用）+（這次新增）會超過 80%？
#    超過 → 等等，先讓最近那次大變動 age out（看 /backup/snapshots 哪天最大、那天 + 7 才清掉）
#    沒超過 → 直接搬

# 4. 看哪天的 snapshot 最大（找出之前最大那次發生在哪天）
sudo du -sh /backup/snapshots/* | sort -h | tail
```

### 小白版的安全行為原則

1. **大批照片進 Immich 之前**先 `df -h /backup` 看一下
2. 如果 `/backup` 已經 80% 以上，**避開**做大量新增（除非你心算過確實放得下）
3. 如果一定要做，可以**多次小批次**（每批 < 20GB），中間隔幾天觀察，比一次倒入安全
4. **5/8 凌晨**等於是你目前這個事件的「自然解套日」（5/1 那 144GB 會清掉）——之後磁碟會降到約 60–70%，就有餘裕了

### 長期解法

如果你預期未來照片量還會持續長大，**500GB 備份盤遲早不夠**——但這是「升級備份盤」的時機問題，不是「策略要避開大搬」的問題。等真的到了瓶頸再升級就好。

## 6. VPN 是什麼？OpenVPN 跟 WireGuard 差在哪？

### VPN 是什麼

**VPN = Virtual Private Network = 在公網上開一條加密隧道**

把網路想像成寄信。預設情況下你寄出去的信是明信片——任何中間經手人（你的 ISP、咖啡廳 Wi-Fi 老闆、被駭的路由器）都能偷看內容。

VPN 就是把整封信塞進一個**密封信封**，外面只看得到「從 A 寄到 B」，內容看不到。

VPN 兩種主要用途：
- **遠端連回家裡/公司的私網**（你 NAS 上 Tailscale 的用途）
- **用 VPN 服務商隱藏自己的位置/IP**（NordVPN、ExpressVPN 那種商用 VPN）

我們現在講的是第一種。

### OpenVPN（2001 年，元老級）

- 程式碼很大（幾十萬行）
- 設定**很複雜**——憑證、ca、key、cert、ta.key、tls-auth、cipher⋯⋯一堆要自己配對
- 加密選項**很多**——可以用很舊的演算法（為了相容）也可以用新的
- 跑在 OS 之外的層（user space）
- 速度比 WireGuard 慢
- 像一把瑞士刀：什麼都能做，但要會用

### WireGuard（2018 年進 Linux 核心）

- 程式碼**極小**（約 4000 行 vs OpenVPN 的數十萬）
- 設定**極簡**——一個小設定檔搞定
- 加密**只用現代演算法**（不給你選舊的，避免有人錯選不安全的）
- 跑在 OS 核心裡（kernel space）→ 速度顯著更快、CPU 用得更少
- 像一把專業手術刀：不能做什麼花俏的事，但該做的事做得極好

### 程式碼少 = 安全嗎？

是的，這是 WireGuard 一個很重要的賣點：**程式碼少 = 容易審查 = 漏洞少**。
4000 行可以一個人從頭看到尾；幾十萬行沒人能保證每個角落都沒 bug。

### 跟你有關的事

- Tailscale 用的是 **WireGuard 當底層引擎**——所以你 NAS 上連線本質上是 WireGuard 在加密
- 但你不會直接用 WireGuard——Tailscale 把那些「設定的麻煩」全部包掉
- 換句話說：你享受 WireGuard 的速度跟安全，但不需要懂 WireGuard 怎麼設

如果哪天你看到「WireGuard」這個詞，可以心裡翻譯成「Tailscale 底下那個現代 VPN 引擎」，不會錯。

## 7. Tailscale 的原理：mesh 怎麼長出來

你說你知道 Tailscale 是 mesh（網狀）但不知道原理。先講「mesh 是什麼」，再拆 Tailscale 怎麼建出 mesh。

### 兩種網路拓撲

**Hub-and-spoke（星狀）—— 傳統 VPN**

```
 Mac ─┐
       ├─→ VPN Server ←─ NAS
 iPad ─┘
```

- 每個 client 連回中心 server
- 兩個 client 要互通，**流量要繞過 server 才能到對方**
- Server 是瓶頸（流量都走它）、也是單點故障（它掛了全部斷）

**Mesh（網狀）—— Tailscale**

```
   Mac ───── NAS
    │  ╲    ╱  │
    │   ╲  ╱   │
   iPad ─── iPhone
```

- 每個設備**直接跟其他設備通訊**，不繞中央
- 速度快（最短路徑）、無單點瓶頸
- **難點**：怎麼讓兩個都躲在自家路由器後面的設備直接連到彼此？這就是 Tailscale 真正在解決的問題

### Tailscale 怎麼長出 mesh：四個步驟

**步驟 1：協調伺服器（control plane）**

當你 Google 登入 Tailscale，雲端有一台**「介紹所」**：
- 記錄誰是你的朋友（同一個 tailnet 的設備清單）
- 記錄每個設備的公鑰是哪個
- 記錄每個設備目前的網路位置（粗略地：在哪個外部 IP、哪個 port 看得到）

**重點**：介紹所**只介紹**，不傳遞你的真實流量。你的資料**從不經過 Tailscale 公司的伺服器**（除了一個例外，下面說）。

**步驟 2：公鑰交換**

- 你每台設備在本地生一對 WireGuard 金鑰：私鑰留在設備上、公鑰丟給介紹所
- 介紹所把「同一個 tailnet 裡每個設備的公鑰」互相發給彼此
- 結果：每台設備都拿到「家裡其他設備的公鑰清單」

→ 這就是為什麼 Tailscale **本身看不到你的流量**：流量是用設備本地的私鑰加密的，Tailscale 公司沒有那把私鑰，它只能看到 metadata（誰連誰、什麼時間），看不到內容。

**步驟 3：NAT 穿透（這段是魔法）**

兩台設備（你 Mac 在咖啡廳、NAS 在家）各自躲在路由器的 NAT 後面。預設情況下：
- 從外面**主動敲門進來**，路由器會擋（NAT 表沒記錄這個連線 → 視為陌生人）
- 所以兩台 NAT 後的設備**沒人能先主動連對方**

Tailscale 用一個叫 **STUN** 的技術做「同時打洞」：
1. 介紹所同時告訴兩台設備：「對方公開可見的 IP:port 是 X」
2. 兩台設備**幾乎同時**送一個封包出去，目標就是對方那個 X
3. 自家路由器的 NAT 看到「我這邊有人主動往那個方向送出去」，會在 NAT 表上記一筆「**這個方向我同意流量回來**」
4. 兩邊同時打了洞，回來的封包都被允許進來
5. 從此兩台設備可以直接 P2P 通訊，不再需要介紹所

→ 這個比喻：兩個朋友家都被柵欄圍起來。介紹所教他們**同時**把信丟出柵欄縫——柵欄會記得「這個方向之前有出去信，這個方向回來的也讓進」。一旦相互打洞成功，他們就能直接互寄信，不用再透過介紹所。

**步驟 4：DERP relay 後備（穿不過去時）**

有些網路特別嚴格的 NAT（叫 **symmetric NAT**，常見於行動網路、企業網路），打洞會失敗。

此時 Tailscale 啟動 **DERP 中繼伺服器**：
- 兩台設備分別連到最近的 DERP（全球幾十個點）
- DERP 幫忙轉發加密封包
- **DERP 看不到內容**（一樣是端對端加密），但會看到 metadata

速度比直連慢一些，但能通——保證任何網路條件下你的設備都連得到彼此。

```bash
# 你想看自己的連線是 P2P 還是走 DERP：
tailscale status   # 直連的會顯示 "direct"，走 DERP 的會顯示 "relay"
```

### 設備換網路會怎樣？

你 iPhone 從家裡 Wi-Fi 走出門切到 4G——它的外部 IP 變了。
- 介紹所馬上知道（iPhone 主動回報新位置）
- 介紹所通知 tailnet 內其他設備「iPhone 換位置了」
- 其他設備跟 iPhone 重新打洞（背景進行）
- 你**完全不會感覺到斷線**——SSH session、Samba 都繼續

→ 這是 Tailscale 比手動 WireGuard 強很多的地方：手動 WireGuard 換網路就要重設、重連。

### 整理一下 Tailscale 的角色分配

| 元件 | 看得到什麼 | 看不到什麼 |
|---|---|---|
| 介紹所（控制平面） | 誰連誰、誰在哪、公鑰清單 | 你的流量內容 |
| DERP 中繼（後備路徑） | 加密封包的 metadata、誰跟誰中繼 | 流量內容（端對端加密） |
| 你自己的設備 | 全部（私鑰只在自己這裡） | — |

這也是為什麼 Tailscale 是商業服務，但**就算 Tailscale 公司被駭，他們也解不開你的流量**——他們手上沒私鑰。

### 跟你 NAS 有關的事

- 你 `tailscale status` 看到的 7 台設備，背後就是這套機制在跑
- 多數連線是 P2P 直連（NAS 在家裡、設備是 4G/Wi-Fi 通常打得通洞）
- 偶爾會走 DERP（網路特別嚴格時），你不會察覺
- 你完全不用碰路由器、不用 port forwarding——介紹所＋打洞兩招就解決了
