## 地基蓋好了，路怎麼走？

上一篇講選 Ubuntu Server 是「給 AI 一個它最熟的家」。但這個家蓋好了，**AI 跟我自己從外面要怎麼走進來**？

回想第二篇〈SSH Key〉的時候我說過一句話：「**SSH 從不對外開放**。」當時這句話沒展開——既然不對外開，那 ClaudeCode 在我筆電上是怎麼有辦法 ssh 到 NAS 的？我手機在外面是怎麼連 Samba 看家裡照片的？

答案是 Tailscale。

它**不是**一個讓你的 NAS 對外開洞的東西。它是一條**只有自家設備走得進的私人巷弄**——讓自己的設備之間互相看得到，但對外面的世界完全隱形。

這篇要回答幾個小白會問的問題：傳統上要遠端連家裡的 NAS 有哪些方法（為什麼那些都不好用）？Tailscale 解決的是什麼問題？我 NAS 上實際是怎麼跑的？另一個叫 Cloudflare Tunnel 的東西跟它是什麼關係？

---

## Tailscale 之前，傳統有兩條路

要從外面連到家裡的 NAS，在 Tailscale 出現之前，你大概只有兩條路。

### 路 A：把 NAS 對全世界開門（port forwarding）

最直覺的做法。你在自家路由器上設一條規則：「外面找我家 22 port 的請求，全部丟給 NAS。」

聽起來簡單，但這等於把 NAS 的 SSH **直接放到馬路上**。
全世界一秒幾百次的自動掃描腳本馬上會找上你——慢慢試 `admin/123456`、`root/password`⋯⋯總有一天會試中。

而且還有一個額外問題：家用網路的 IP 是動態的，你 ISP 想換就換，今天連得到、明天可能就找不到家。要解決得花錢買固定 IP、或設動態 DNS。

### 路 B：自己架 VPN（OpenVPN 或 WireGuard）

工程師通常會選這條：在 NAS 上自己架一個 VPN server，每個裝置裝 client，連上後就「像在家裡一樣」。

安全性比路 A 好太多——VPN 是加密通道、用憑證驗證、不是開洞讓全世界進來。但是⋯⋯

> 順帶提一下，OpenVPN 跟 WireGuard 是兩個不同的 VPN 工具——OpenVPN 是元老（2001）、設定複雜、什麼都能配；WireGuard 是 2018 才進入 Linux 核心的後起之秀，程式碼極小（4000 行）、設定極簡、速度快得多。但兩個都是「VPN 引擎」這個層級，需要你親自去配的。

不管選哪個，你要自己處理：
- 在路由器開 port（又繞回路 A 的問題）
- 生憑證、發給每個裝置
- 處理 NAT 穿透（家用網路通常躲在運營商的大 NAT 後面，兩台都在 NAT 後面的設備直接通訊很麻煩）
- 設防火牆規則
- 偵測連線斷掉自動重連
- 換網路時要重新協調

對工程師可行，**對小白幾乎不可能搞定**。

所以我們需要一個「VPN 該有的安全 + 不需要動腦的設定」。Tailscale 就是這個東西。

## Tailscale 是什麼：私人巷弄

我用一個比喻來解釋。

**公網**像大馬路。所有電腦都站在路邊，IP 就是門牌。誰都看得到、誰都能來敲門。對外開服務就是把家門開到馬路上。

**Tailscale** 不在馬路上做事。它在現實之上**多畫了一條只有自家設備能進的小巷**。

每台設備（你的 NAS、Mac、iPhone⋯⋯）裝上 Tailscale、用同一個 Google 帳號登入，就**自動加入這條小巷**。在這條小巷裡，每台設備拿到一個 `100.x.x.x` 開頭的「巷弄門牌」（外面的世界完全看不到也走不進）。

巷弄裡的設備**直接看得到彼此**，像在同一個區域網路。

具體效果：

- 我在咖啡廳用 Mac、`ssh gakes@100.104.47.27` 直接連到家裡 NAS——完全沒碰路由器、沒開 port、沒申請固定 IP
- 我在外面用 iPhone 開 Samba 連 NAS 共享，速度跟在家一樣
- 家裡網路的 IP 換了？沒關係——巷弄門牌不會變

## 它是怎麼做到的（小白版）

簡短地把黑盒拆開來看一眼，不深入技術。

**底層是 WireGuard**——上一節提過的那個現代 VPN 引擎，加密強、速度快。Tailscale 把 WireGuard 自己很硬的部分（手動發金鑰、設規則、處理 NAT）**全自動了**：

- 設備之間的金鑰交換 → Tailscale 後台處理
- 兩台設備互相找位置 → 它的伺服器當「介紹所」
- NAT 穿透（兩台都躲在路由器後面的時候） → 它的演算法搞定大部分情境
- 真的穿不過去 → 走它的中繼伺服器，慢一點但能通

關鍵是 Tailscale 公司**只看得到「誰是誰、誰在哪」**（metadata），**看不到你的流量內容**——因為加密用的私鑰只在你自己設備上。

我寫這個系列的時候特別把 Tailscale 的原理拆解成另一份學習筆記放在 [drafts/_concepts.md](#)（如果你好奇「同時打洞」這個技巧到底怎麼運作，那邊有比較完整的解釋）。這篇文章就不展開了。

> 你只負責一件事：在每台設備上裝一次 Tailscale、用 Google 登入。做完就好了。剩下全部它幫你搞定。

## 我家現在的 Tailscale 巷弄

把實際情況攤出來看比較有感。

我目前在 Tailscale 私網裡有六台設備（七筆紀錄，其中有一筆是舊 Mac 重新加入時留下的紀錄，之後我會清掉）：

| 設備 | Tailscale IP | 角色 |
|---|---|---|
| labserver | 100.104.47.27 | NAS 本人 |
| macbook-air | 100.120.55.119 | 我的 Mac |
| iphone-11 | 100.119.155.21 | 我的手機 |
| ipad-10th-gen | 100.78.89.41 | 主 iPad |
| ipad-mini-6th | 100.80.104.77 | 翻書用的 iPad mini |
| desktop（GakePC） | 100.124.183.38 | 我的桌機 |

實際應用：

- 我從 Mac/iPad/手機任何裝置，都用 `100.104.47.27` 連 NAS
- 從家裡 Wi-Fi 內也可以用區網 IP `192.168.1.182` 直連（短一點、更快）
- 但離開家後，**只有 Tailscale IP 連得到**——這條巷弄就是我的遠端通道

而且——回到第二篇〈SSH Key〉那兩把鑰匙的故事——**第二把鑰匙（ClaudeCode）走的就是這條路**。

我筆電上的 ClaudeCode 也裝了 Tailscale。它 ssh 到 NAS 時，是走 `100.104.47.27` 這個 Tailscale 私網位址，不是走公網。它的 SSH 流量從來沒上過公網，全程都在我的私人巷弄裡。

#2 給 AI 一把鑰匙——鑰匙是 SSH key。
門在哪？答案：**在 Tailscale 巷弄裡**。

## Tailscale vs Cloudflare Tunnel：兩條路服務不同的人

這部分對小白特別容易混淆。我 NAS 上**同時用兩個工具**——Tailscale **跟** Cloudflare Tunnel——它們不是替代關係，是分工。

| | Tailscale（巷弄） | Cloudflare Tunnel（街道） |
|---|---|---|
| 給誰用 | 自己人（自家設備、AI 的筆電） | 全世界（任何瀏覽器） |
| 連得到嗎 | 對方要先連 Tailscale | 隨便瀏覽器打網址就能 |
| 用來做什麼 | SSH、Samba、看內部 log | 對外網頁服務（Immich、LINE Bot 等） |
| 看見的位址 | `100.x.x.x` | `xxx.gakes.net` |

實際應用對照：

- 我自己在外面遠端管 NAS → 走 Tailscale（要登入 Tailscale 才走得進）
- 我的 LINE Bot 要收 LINE 平台 webhook → Cloudflare Tunnel（LINE 是「全世界」之一，它沒有 Tailscale 帳號）
- 我太太要看 Immich 照片 → Cloudflare Tunnel（不需要她裝 Tailscale）
- 我自己要看 Immich → 兩個都行，但 Cloudflare Tunnel 比較方便

一句話總結：**Tailscale 是讓「我自己」進來的路，Cloudflare Tunnel 是讓「全世界」進來的路。**

```mermaid
graph TB
    WORLD[🌍 全世界<br/>瀏覽器、LINE Webhook、家人]
    ME[👤 我自己<br/>Mac、iPad、iPhone]
    AI[🤖 ClaudeCode<br/>跑在筆電上]

    WORLD ==>|Cloudflare Tunnel<br/>xxx.gakes.net| FE[對外服務<br/>nas-dashboard / Immich / LINE Bot]
    ME -.Tailscale 私人巷弄<br/>100.104.47.27.-> CORE[NAS 內部<br/>SSH / Samba / log]
    AI -.同一條巷弄.-> CORE

    FE -.同一台機器.-> CORE
```

這個分工建立了一個 mental model 我覺得對小白特別重要：**遠端存取不是「對外開不開」這種非黑即白的事**——**是分對象決定走哪條路**。

家人要看的東西走街道。自己人要管理的東西走巷弄。AI 要進來幹活的也走巷弄。每條路有它服務的對象，不混在一起。

## 私人巷弄的哲學

從技術回到主題。

**公網是馬路，巷弄是信任的延伸。**

馬路上你可以擺攤（對外服務），但生活還是發生在巷弄裡（管理、自己人、AI 協作）。Tailscale 不是讓你「躲起來」，是讓你**清楚分開**「給世界看的東西」跟「給自己用的東西」。

這跟我整個 NAS 系列的精神一致：**每個設計決策，都是把不同對象的需求分開放在對的位置上**——硬碟分熱區/溫區/冷區、服務分對外/對內、連線分巷弄/街道。

到這裡，串起這個小系列的四篇就是這樣的：

> #2 給 AI 一把鑰匙進來
> #3 給 AI 一份家規（INFRA.md）
> #4 給 AI 一個它最熟的家（Ubuntu Server）
> **#5 給 AI 一條只有自家人能走的路（Tailscale）**

從第一篇硬體規劃開始一路到這裡，整套 NAS 不是「裝了一堆軟體」——是一個**有設計的小生態**。對自己負責、對 AI 開放、對世界謹慎。

每一個設計決定都跟「我這個家裡誰是誰、什麼東西放哪、誰可以進哪」有關。

寫到這裡，我發現 NAS 折騰其實不是技術問題——是一個**怎麼安排空間、權限、信任**的問題。技術只是把這些抉擇實作出來的工具。

## 想自己也架 Tailscale？跟 AI 這樣說 →

> 「我家有 NAS、Mac、iPhone，我想用 Tailscale 讓我從外面也能 SSH 進 NAS、用 Samba 看家裡照片。請帶我把每台設備設好、確認彼此通得到、**告訴我每一步在做什麼**。」

加上「**告訴我每一步在做什麼**」這句很重要——它會在過程中順便幫你建立 mental model，下次出問題你能自己 debug 一點。
