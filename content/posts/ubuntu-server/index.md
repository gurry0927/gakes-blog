## 地基也是設計決策

上一篇我寫到 NAS 憲法是這台機器的家規。但家規寫在哪一種地基上？

NAS 圈大概有三條路可以走：**TrueNAS**、**Unraid**、**Ubuntu Server**。前兩個是「NAS 專用 OS」，第三個是「一般 Linux 伺服器」，所有東西要自己動手裝。

按直覺，「專用」聽起來比較專業——就像買菜刀會選刀具店、買跑鞋會選運動品牌。但我選了第三個，那個「什麼都自己來」的選項。

理由其實很無聊：**我選的不是最好的，是最熟的**——對我熟，對 AI 也熟。

這篇要把這個選擇講清楚。包括：另外兩個選項其實長什麼樣、為什麼我看到它們會心動、最後為什麼還是放棄、以及這個選擇我**實際失去**了什麼。

---

## NAS OS 圈的三選一

對沒玩過 NAS 的人來說，這三個名字大概是這樣：

| | TrueNAS | Unraid | Ubuntu Server |
|---|---|---|---|
| 定位 | NAS 專用 OS | NAS 專用 OS（半商用） | 一般 Linux 伺服器 |
| 賣點 | ZFS 自我修復、企業級可靠 | Parity 容錯、混合容量硬碟 | 自由、什麼都自己組 |
| 介面 | 漂亮的 Web UI | 漂亮的 Web UI | 黑黑的終端機 |
| 費用 | 免費 | 約 $59 USD 起跳的授權 | 免費 |
| 對小白 | 友善但要遷就它的設計 | 最友善 | 不友善（要自己上） |

讀一眼有概念就好。重點是後面幾節，為什麼我選了那個「不友善」的。

---

## 我看到前兩個其實是心動的

寫這篇文章我得對自己誠實——TrueNAS 跟 Unraid 不是「不好」，是真的有它們的優勢。

**ZFS 自我修復**（TrueNAS 的招牌）

ZFS 是一種比一般 Linux 預設的 ext4 厲害很多的檔案系統。它能幫每個檔案算「指紋」，定期掃描，發現檔案有「位元腐敗」（一張照片某幾位元因為各種怪原因自己翻面）的時候，會自動從備援資料修回來。

這對長期保存照片是真的有用。爺爺奶奶的數位遺物可能放二十年都不會被打開一次——你要的是它**靜靜地待在那裡不會默默壞掉**。

**Parity 容錯**（Unraid 的招牌）

Unraid 用一種叫 Parity 的設計，可以讓你用一顆 4TB ＋ 一顆 2TB ＋ 一顆 1TB 組成一個容錯陣列。**任何一顆掛掉**都能用其他盤把它救回來。

對誰最有用？「家裡剛好翻箱倒櫃挖出幾顆不同大小舊硬碟」的人——這完美命中我第一篇的開場。寫到這一條我必須承認，我當下真的有心動三秒。

**GUI 設定一切**

兩個 NAS 專用 OS 都有漂亮的 Web 介面。新增 Samba 共享、設備份排程、加新服務⋯⋯都是滑鼠點點點的事。學習曲線比 Ubuntu Server 平滑非常多。

**那為什麼還是選 Ubuntu Server？** 因為我有兩個比這些優勢都更重要的需求。

---

## 兩個「熟」

我的選擇歸結成兩個字：**熟**。

### 熟之一：對我熟

這部分要先把背景講清楚，免得聽起來像炫耀。

我是 AI 工程師。日常工作就是在 Ubuntu 機器上跑模型、訓練、Docker、GPU 環境。不是 sysadmin 等級的熟、不會自己寫 kernel 模組那種——但 `apt install`、`systemctl status`、`docker compose up` 這些指令，至少不會像看天書。

這個「淺熟」對 NAS 規劃影響很大。

換 TrueNAS 等於換一套思考框架——它有自己的 plugin 系統、自己的 dataset 概念、自己的設定哲學。對完全沒碰過 Linux 的人這可能是好事（因為什麼都不熟、那就學它的就好）。但對已經會走路的人，**學「不一樣的走法」是負擔**。

我選 Ubuntu 不是因為它最強，是因為**我已經知道怎麼跟它說話**。出問題時知道去哪查、看 log 看哪個檔、要重啟服務記得是 `systemctl restart` 不是按某個按鈕。這些「無意識的肌肉記憶」讓我能把腦力花在「設計」而不是「翻文件」。

### 熟之二：對 AI 熟

這個維度是我選 Ubuntu 才意識到的，但一旦意識到、影響非常具體。

跟 AI 協作有一個道理：**你給它的環境越主流，它越能無縫接手**。

我 NAS 上的所有東西都是跟 AI 一起架起來的（其實這個 blog 系列就是一份證據——你正在讀的這篇文章背後就是 AI 跟我來回討論寫成的）。我會問它「幫我設計新服務的 compose」、「這個 cron 為什麼沒跑」、「這個 log 是什麼意思」。

如果我跑 Ubuntu Server，它的回應幾乎是即時且精準的——因為 Ubuntu 在它訓練語料裡是 default 設定，它有非常豐富的 context。

但如果我跑 TrueNAS Scale 呢？我跟它講「TrueNAS 怎麼做 X」，它會猶豫，會給通用 Linux 答案再加一句「但你的 OS 是特殊的，建議查官方文件」，會開始浪費 token 跟我確認狀況。它能幫上忙，但慢、不準、需要我提供更多 context。

差異累積起來很可觀。長期看：

- 跑 Ubuntu = AI 直接給你能執行的指令
- 跑 TrueNAS = AI 給你「方向」，然後你自己去查 TrueNAS 怎麼做

這不是 TrueNAS 不好——是「AI 的訓練資料分布」這個現代才存在的因素，把「主流選項」的成本壓得比小眾選項低很多。

換句話說，我把「**對 AI 熟**」當成一個明確的設計變數來考慮。在 2026 這個 AI 跟人協作越來越深的時代，**選擇主流就是選擇省力**。

## 全用 Docker = NAS OS 的特殊功能我用不到

選 Ubuntu Server 還有一個基本前提：**我所有服務都跑 Docker Compose**（這是 NAS 憲法第四條）。

當你決定全用 Docker 之後，NAS 專用 OS 那些招牌功能其實**就被你架空了**。

- TrueNAS 有 Jails、Apps、ZFS dataset 跟 Docker volume 整合——這些優勢我用 Docker Compose 跟 bind mount 取代了
- Unraid 有 Parity 容錯、有 Mover——這些我用三顆盤分工 + rsync hardlink 7 天 snapshot 取代了（第一篇有寫）
- 兩者都有的 Web UI 設定服務——我用自己寫的 nas-dashboard 取代了（之後會專文寫）

等於是買了一雙登山鞋，只用來走平地。專用設計浪費掉。

反過來說：**當你的設計是「全 Docker、自管備份、自寫面板」，你就不需要 NAS 專用 OS 了**——剩下的問題只是「哪個 Linux 跑 Docker 最順、最熟」。

答案就是 Ubuntu。

## 我失去的東西（誠實寫一下）

文章寫到這裡聽起來太順——好像 Ubuntu Server 全勝、TrueNAS / Unraid 全敗。實情不是這樣。我選 Ubuntu Server **真的有失去**東西：

**沒有漂亮 GUI**
所以我自己寫了一個 nas-dashboard。對熟程式碼的人是「想要什麼就做什麼」的自由；對不會寫程式的人是「就這樣將就」的限制。

**沒有 ZFS self-heal**
我的 ext4 + rsync hardlink 抓得到「人為失誤」（誤刪、覆蓋），抓不到「位元腐敗」（檔案在硬碟上自己悄悄壞掉）。10 年後我可能會發現某些舊照片有奇怪色塊，那就是 bit rot。我認了——目前照片量還沒大到必須面對這個問題。

**沒有 Parity 容錯**
我的備份策略是 rsync 7 天快照——能應付**人為失誤**（誤刪、誤改），但**不能應付硬碟本身突然壞 sector**。如果哪天 `/data` 那顆 2TB HDD 真的物理掛掉，我得從備份盤還原資料，期間 NAS 是停的。

對我來說：「停個幾天等蝦皮送新硬碟」可以接受——所以放棄 Parity 我願意。對不能停機的人就不行了。

**設定全部自己來**
裝 Tailscale、設 fail2ban、寫 cron、調 hdparm spindown 規則⋯⋯每一件事我都得自己來。學習曲線很陡。但學會之後，**這台機器的每一個角落我都知道在做什麼**——這對長期維護有不可替代的價值。

寫到這裡我意識到，這幾個 trade-off 其實有一個共通點：**我用「主動性」交換「自動化」**。NAS 專用 OS 把很多事情自動化好了，代價是你得照它的方式想。Ubuntu 把所有自動化都拆開來給你看，代價是你得自己組。

## 「最佳」vs「最熟」

寫這篇我體會到一件事：大多數技術選擇沒有「最好的」答案，只有「最適合你當下的」答案。

而「適合」的標準裡面，「**熟**」常常被低估。

人們追新、追酷、追 hype——但 NAS 是要陪你跑十年的東西。十年裡你會 debug、會升級、會搬遷、會半夜醒來修壞掉的服務。在這些時刻，**熟讓你做決策快、debug 快、跟 AI 協作快**。

而「熟」是有複利的：你越熟，越多東西能在這個地基上跑、就越熟。

我這台 NAS 跑 Ubuntu Server 跑了一個多月，沒發生過任何「卡在 OS 本身」的問題。所有時間都花在「設計什麼新功能」、「優化哪個服務」這種有價值的問題上。地基沒給我添麻煩——這就是「熟」的紅利。

下一篇要講的是這條第 0 條的另一個面向——選對 OS 只是地基，**AI 跟我自己要怎麼從外面走進這個地基**？這就是 Tailscale 的角色。

---

地基不是越強越好，是越熟越好。**熟的地基，讓你能蓋出別人蓋不出的房子**。

## 想自己也評估該選哪個 NAS OS？跟 AI 這樣說 →

> 「我手邊有 [你的硬體]，會用來放 [照片/影片/服務]，我熟悉 [你會的工具，譬如 Linux / Docker / 完全不會]，預算 [N]。請幫我比較 TrueNAS、Unraid、Ubuntu Server 我比較適合哪個，並說明判斷依據。」

「適合」沒有標準答案——把你的條件講清楚，AI 給的建議才會貼你。**它需要的是你的限制條件**，不是「最佳解」。
